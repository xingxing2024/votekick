# VoteKick — 玩家投票踢人

Paper/Purpur 插件：任意玩家发起投票，在线玩家在时限内投票，同意票达到门槛就把目标踢出服务器。

## 安装

1. 把 `target/VoteKick-1.0.0.jar` 放进服务器的 `plugins/`。
2. 启动服务器，生成 `plugins/VoteKick/config.yml`；改完配置用 `/vk reload` 生效，不需要重启。
3. 禁入名单 `plugins/VoteKick/bans.txt` 在有第一次投票通过后自动生成，可以手改。

## 支持的版本

- **一个 jar 通吃 1.21.1 ~ 26.x**：编译基线是 `paper-api 1.21.1` + Java 21，只用到 1.21 就有的 API，`plugin.yml` 里 `api-version: '1.21'`。1.21.1 及以上（含 1.21.7、26.3）都能直接跑。
- **Folia 可用**：`folia-supported: true`，调度全部走 `Schedulers`（共享状态在全局区域线程，玩家界面/实体在该玩家自己的线程）。启动日志会打印 `调度模式：Paper 主线程` 或 `调度模式：Folia 区域线程`。
- 需要 Java 21 或更高。

## 指令

| 指令 | 说明 |
| --- | --- |
| `/vk` | 打开图形界面（无参数，仅玩家可用） |
| `/vk <玩家> <理由>` | 发起投票，**理由必填**（最多 60 字，超出截断） |
| `/vk confirm` | 确认恶意投票提醒，确认后投票才真正开始 |
| `/vk yes` / `no` | 投同意票 / 反对票；同一人重复投视为改票 |
| `/vk cancel` | 放弃待确认的发起，或取消当前投票（发起者本人或 `votekick.admin`） |
| `/vk history [玩家] [页码]` | 查投票记录，每页 10 条（`votekick.admin`） |
| `/vk reload` | 重载配置（控制台也能用） |

别名 `/votekick`（老习惯照样能用）。`yes/no` 也接受 `y/n/同意/反对`。

## 恶意投票提醒（发起确认）

发起不是点一下就生效：通过全部规则检查后，发起者先拿到一段可配置的提醒（报假理由、拉人报复、恶意围攻会被记录并处罚），必须在 `settings.confirm-seconds` 秒内输入 `/vk confirm` 或在界面里点确认，否则这次发起自动作废。

- 提醒内容、行数、颜色全部写在 `messages.confirm-warning`，支持写成多行列表，也可以用 `%target% %reason% %time%`。
- 想全服都看到这次发起，把 `settings.confirm-broadcast` 设为 `true`。
- 不想要这一步就设 `settings.confirm-seconds: 0`，发起后立即开始投票。
- 提醒阶段的目标下线、投票被别人抢先开始、冷却未到，都会让确认失败并给出对应提示。

## 图形界面

`/vk` 打开的界面会跟着状态自动切换，打开期间每秒刷新：

- **选人列表**（54 格）：显示所有可被投票的在线玩家头像（排除自己与 `votekick.immune`），按名字排序，每页 45 人；底栏是上一页 / 页码 / 下一页 / 关闭。
- **确认发起**（27 格）：左边是提醒纸（整段提醒文字）、中间是目标头颅，下面确认 / 放弃；倒计时每秒刷新。
- **投票界面**（54 格）：目标头颅（含原因）、同意（绿块）、实时进度条（时钟）、反对（红块）、关闭；发起者或管理员还会看到取消按钮。
- **点头像 → 关界面 → 在聊天里输入理由**：理由必填，输入 `cancel`（或中文「取消」）作罢；理由这条聊天不会广播出去，60 秒不输入自动失效。
- 状态变化时已打开的界面会自动切换；界面里的点击和拖拽全部被拦截，物品只是按钮。

## BOSS 条

投票开始后，所有在线玩家屏幕顶部出现实时进度条：

- 文本：目标、同意/所需、反对、剩余秒数（`messages.bossbar`）。
- 进度按「同意票 / 所需票数」填充，颜色随进度从红 → 黄 → 通过时绿。
- 每秒刷新；中途进服的玩家自动补上，退服自动移除，投票结束立刻消失。
- 不需要可在配置里设 `settings.bossbar: false`。
- 聊天里同时广播一行可点击的 `[ 同意 ]` / `[ 反对 ]` 按钮，手机上点一下就能投票。

## 踢出后的禁入

投票通过后，目标不只是被踢出：在 `settings.ban-seconds`（默认 `3600` 秒 = 1 小时）内不能进服。

- 按 UUID 记在 `plugins/VoteKick/bans.txt`，重启也有效；换名字、退服重进都躲不掉。
- **目标在投票进行中下线不会让投票作废**：票照样算，通过后照样记禁入，他下次连服就会被挡在门外（全服会收到一句「目标已下线，投票继续」）。靠下线逃票这条路被堵死了。
- 被挡时看到的界面是 `messages.ban-screen`：剩余时间、当时的理由，都能改，也能只留一部分（删掉 `%reason%` 就不显示理由）。
- 投票通过、禁入生效时全服再播一行 `messages.ban-applied`。
- 不想禁入就把 `settings.ban-seconds` 设成 `0`，回到「只踢不禁」；这时目标中途下线仍然会终止投票（既禁不了，人也踢不到，继续算票没意义）。
- 管理员要提前解禁：删掉 `bans.txt` 里对应的那一行，再 `/vk reload`。
- 这里的禁入由插件自己拦登录，不写进原版 `banned-players.json`，`/banlist` 里看不到。

## 投票记录

每次投票结束都会往 `plugins/VoteKick/logs/votes-日期.log` 追加一行，按天分文件、UTF-8：

```
2026-10-25 18:17:35 | 通过 | 目标=VoteB | 发起=VoteA | 同意=2 反对=0 所需=2 | 理由=刷屏广告
```

结果词有：通过 / 未通过 / 超时作废 / 被取消 / 目标离线（文字在 `messages.log-*` 里改）。
管理员可以直接看文件，也可以用 `/vk history [玩家] [页码]` 在游戏里分页查（新记录在前，`votekick.admin`，控制台也能用）。

## 权限

| 权限 | 默认 | 说明 |
| --- | --- | --- |
| `votekick.start` | 所有玩家 | 发起投票 |
| `votekick.immune` | OP | 不能被投票踢出（OP 默认免疫，给管理组加上即可） |
| `votekick.admin` | OP | 取消任意投票、查记录、重载配置 |

## 配置要点（`config.yml`）

- `settings.percent`：通过门槛比例，按「有资格的在线玩家」计算，默认 `0.6`。
- `settings.min-votes`：最少同意票，默认 `3`。实际门槛 = `max(min-votes, 向上取整(人数 × percent))`。
- `settings.duration-seconds`：投票时限，默认 120 秒，超时未达标作废。
- `settings.cooldown-seconds`：同一玩家两次发起的间隔，默认 300 秒。
- `settings.confirm-seconds`：发起确认窗口，默认 30 秒；`0` = 不需要确认。
- `settings.confirm-broadcast`：确认提醒是否广播给全服，默认 `false`。
- `settings.bossbar`：投票期间是否显示全服 BOSS 条，默认 `true`。
- `settings.ban-seconds`：投票通过后的禁入时长（秒），默认 `3600`；`0` = 只踢出、不禁入。
- `messages.*`：全部提示文本，支持 `&` 颜色代码和 `%占位符%`；`kick-screen` 是目标被踢时看到的界面文本，`ban-screen` 是禁入期内登录时看到的界面文本（`%time%` 剩余时长、`%reason%` 当时的理由），`ban-applied` 是禁入生效时的全服播报，`target-offline` 是目标中途下线那句，`gui-*` 是界面文本，`confirm-*` 是恶意投票提醒与确认提示，`bossbar` 是 BOSS 条文本，`log-*` 是记录文件里的结果词，`history-*` 是查询界面的排版。
- `messages.duration-hour` / `duration-minute` / `duration-second`：时长文案，`%value%` 是数字，只拼非零的部分（3600 秒 → `1 小时`）。想显示成 `1h5m` 就改这三行。
- 任何提示都可以写成多行列表（每项一行），例如 `confirm-warning`、`ban-screen`；单行字符串里也可以直接用 `\n`。

## 行为约定

- 发起投票必须填写理由：指令里直接写在玩家名后面，GUI 里点头像后在聊天里补；理由不超过 `settings.max-reason-length`。
- 通过检查后先提醒恶意投票的后果，发起者确认才真正开始；确认窗口内不确认就作废，且不消耗冷却。
- 同一时间只允许一场投票，也只有一个待确认的发起，避免刷屏和并发计票混乱。
- 投票名单在发起时固定：之后进服的玩家不能参与本次投票，中途退出的人仍计入门槛。
- 所有人投完但同意票不够时立刻判定失败，不用等满时限。
- 通过后按 UUID 禁入 `settings.ban-seconds` 秒，人在不在线都生效；目标靠中途下线躲不过投票。
- 禁入只拦登录，不封号、不写原版封禁名单；需要真封禁请配合封禁插件。
- 目标被踢后，发起者仍受冷却限制，防止连续针对同一玩家。
